# V4：末作业按实际候选估价

日期：2026-11-14。基线是正式 85 分源码，SHA256 `21ab5033ed9052e37b691c8f632029b181fe824f9f612cea9364e21bd8ab985c`，训练对照为 `results/v3_final_aggressive/train`。本轮不改根目录、不访问独立验证集或网站、不提交。

## 动机与边界

主代理追踪发现，一部分未完成工作流只剩一个作业。旧估价在此时仍可能使用代表机器的冷缓存规划工期，并把安全系数留下的一部分当前作业计划费用当成“其它未完成作业费用”。这可能挡住某台暖缓存机器上的实际可盈利候选，但诊断样本数量本身不能证明这些流程都可救回。

两个固定结构版本都严格要求：

`finished_jobs + 1 == job_count && job.status == 0 && unfinished_predecessors == 0`

在合法事件和 DONE 不可逆的前提下，这保证除了当前待运行作业之外，其它作业均已完成，当前没有同流程的其它运行中作业。此时不需要为未知后继预留费用或尾长。

## 两个版本

1. `place`：只修复 `place_job` 的逐机器候选估价。尾长和其它作业费用取 0；候选完工跨度取该机器真实准备时间加估计运行时长；乐观跨度取真实准备时间加 `max(1,0.72*估计运行时长)`。新来的单作业流程也适用。真实镜像、传输、CPU 费用与输入可达性仍完整计算。
2. `rescue`：包含上述修复，另给粗排序增加救急入口。只对**已经开工**、仅剩一个就绪作业、且原估计利润不为正的流程，计算“零准备时间的混合预计收益减全场最低 CPU 单价运行费”。若该估计乐观利润为正，赋予其 0.15 倍的排序利润，并以无准备运行时长作为排序工期。最终是否启动仍由 `place_job` 对真实机器、真实准备量和全部实际启动费用把关。没有给大量新单作业流程增加新的粗筛入口。

这里的“乐观利润上界”仅是给定运行时长估计后的模型上界，不能当作未知真实时长下的数学保证。修改的是调度估价字段，不是 BILL、SLACK、LRU 或配额账本。

## Train16 对照

全部 32 次运行对账正确、零非法指令。

| 版本 | 全16例总利润变化 | 范围内14例总变化 | 范围内等权均比 / 中位比 | 范围内升 / 降 / 平 | 边界2例总变化 |
| --- | ---: | ---: | ---: | ---: | ---: |
| place | -0.0998% | +0.1133% | 1.00759 / 1.00167 | 7 / 6 / 1 | -0.8834% |
| rescue | +0.0852% | +0.1795% | 1.01997 / 1.00597 | 9 / 5 / 0 | -0.2614% |

`rescue` 最好场景 `slow_01` +12.82%，最差 `slow_00` -2.30%；`place` 最好 `small_01` +9.00%，最差 `slow_00` -2.13%。改动并未在所有场景上提高利润；救回更多已投入流程也可能挤掉其它有利任务。

两者相比，完整 `rescue` 在范围内多数场景和中位比上更好，可作为主代理独立新世界验证的候选，但现有总利润增幅很小，不应声称已证明显著提分。

打包后 ASCII 源码 `place` 55,283 字节、`rescue` 55,942 字节；训练粗筛最大 CPU 分别约 0.625 / 0.65625 秒，均不是正式环境时限保证。
