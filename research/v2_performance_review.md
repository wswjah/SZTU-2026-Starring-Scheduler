# V2 纯性能复查

日期：2026-11-13。正式 84 分版本保持冻结；本次没有新提交，也没有修改 main.cpp 或 submit.cpp。

## 结论

未建立稳定超过 5% 的性能收益，因此所有本次候选仅保留作实验，不建议替换正式版本。原目标降低 CPU 15% 未达到。

## 测量与验证

抽样计数显示，最大拓扑例调用镜像预览 1,475,937 次，复制 LRU 双缓存 1,372,953 次；以机器、镜像和机架缓存版本为键的精确缓存潜在命中 492,808 次（约 33.4%）。故障例潜在命中约 42.5%。兼容位清理实际仅在机器故障后发生，并非每 tick 无条件清理。

精确缓存候选 candidates/v2_fast.cpp 在 16 个训练例和 4 个压力例上，利润、费用分项、完成统计等整条评测报告均与正式版逐例相同，且零对账错误、零非法指令。额外查表和工作集抵消了拷贝节省：严格串行、按用例配对、轮次交替先后顺序，3 轮共 120 次运行中，训练集累计 CPU 15.03125 → 14.65625 秒（降低 2.49%），压力集 8.90625 → 9 秒（增加 1.05%）。完整逐次记录位于 results/v2_memo_timing/runs.json，汇总位于 timing_summary.json。

最后一组只作单轮压力初筛，不据此宣称稳定收益：

| 版本 | 4 例累计 CPU 秒 | 整条评测报告等值 |
| --- | ---: | --- |
| 移除强制循环展开 | 3.015625 | 是 |
| O2 | 3.015625 | 是 |
| 延迟规划 LRU 构造，去除机器候选临时 vector | 3.015625 | 是 |
| Os | 3.296875 | 是 |

这些初筛数字没有显示值得继续验证的改善。各次运行均保存在相应 results/v2_*_stress 目录；未丢弃不利结果。未对候选输出流做逐字节对比，因为没有候选达到性能晋升门槛；本次“等值”证据指整条评测报告，而不是已证明所有输出指令逐字节相同。

Windows 本机测量不等于 OJ Linux 时间承诺；正式版此前 OJ 929 ms 的时间余量风险仍存在。
