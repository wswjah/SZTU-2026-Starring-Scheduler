# V4：截止窗口内保护已接纳流程

日期：2026-11-14。基线为正式 85 分源码，SHA256 `21ab5033ed9052e37b691c8f632029b181fe824f9f612cea9364e21bd8ab985c`。本轮只创建两个结构候选，未改根目录、未访问独立验证集或网站、未提交。

## 动机与原式差异

主代理的追踪发现，已开工但未完工流程的花费较大，值得检查是否在“眼下配额空闲、但未来资源已承诺”时仍过度接纳。原 `ahead` 等待惩罚会在剩余配额足够支持新流平均核数时接近零，而且 `place_job` 随后的精算会覆盖工期。

新候选给新流程增加可解释的机会成本，不只是再调等待系数。按每个租户祖先和主要机架分别汇总已接纳流程，按最后仍可获得收益的时刻排序，保留截止前累计核时与预计净收益前缀。

对新流程盈利窗口 `H`，若其预计核时超过 `capacity*H−已承诺核时` 的剩余预算，就把可能挤掉的核时乘以原有流程的平均预计净收益/核时，计作影子机会成本。多个祖先和机架约束取最大值，避免重复收费。成本只参与排序和真正 RUN 前的准入判断，不记入 BILL、不改变可行性、不新增 KILL。高价值新流仍可凭较高净收益越过机会成本。

每次新流程首次 RUN 后，立即登记整条剩余流程的承诺，避免同一 tick 后续新流程仍看见旧的空闲预算。已开工流程不被新门槛拦截，也没有固定流程数上限。

## 两个结构版本

1. `edf`：只计入在新流程盈利窗口内到期的现有承诺，即截止需求预算。
2. `reservation`：除上述承诺外，对更晚到期流程按“新窗口/其剩余窗口”计入平均预约需求与价值。

只把模型当前预计仍有正净收益的已开工流程作为有价承诺；核时按现有时长估计并扣去当前已估计完成部分。该模型不能预知真实时长或将资源预算视为硬保证。

## Train16 结果

两个候选各完整运行训练 16 例；全部 **32 份评测 report 字符串逐例与 85 分基线完全一致**，包括利润、各项费用、完成数量和中断统计。全部对账正确、零非法指令。因此范围内与边界利润变化都为 0，不能支持正式提交或晋升。

打包后 ASCII 源码分别为 58,414 / 58,534 字节，低于 64,000。训练粗筛最大 CPU 约 0.828125 / 0.765625 秒；这不是正式时限校准。增加的计算没有换来当前集合中的利润收益。

## 计数诊断：不是实现未生效

探针只增加统计，不改变决策；抽检报告与正常候选相同。

| reservation 场景 | 非零机会成本查询次数 | 查询中最大窗口负载比 | 实际首次 RUN 的流程数 | 其中带非零机会成本 |
| --- | ---: | ---: | ---: | ---: |
| standard_00 | 1,853 | 1.023794 | 982 | 0 |
| heavy_00 | 1,342 | 0.866511 | 1,674 | 0 |
| small_01 | 473 | 0.821912 | 275 | 0 |

原策略确实遇到过会触发机会成本的候选，但它们本来就未被接纳；真正开工的流程没有让这个预算模型新增绑定约束。这解释了结果完全不变。

这个结论只适用于本轮的“预计仍有正净收益的承诺”和估计核时，**不能证明真实未来容量始终充足，也不能排除模型已判不盈利但仍占着机器的作业造成阻塞**。未完工花费大不等价于总核时窗口过载；DAG 串行、准备和传输、单机碎片、非抢占以及未知真实时长仍可能是主要原因。本轮没有再新增第三个策略或扫描系数。
